# 시간·자막·영상 합성 규칙

## 좌표와 시간 단위

출력 캔버스는 1080×1920, 30fps입니다. 스타일 좌표와 글자 크기는 이 캔버스의 픽셀 단위입니다. 내부 시간은 초 단위의 Python `float`이며 원본·출력 시각을 구분합니다. 자막과 클립 범위, 삭제 목록은 원본 기준으로 저장합니다. 브라우저에 표시되는 소수 자릿수보다 내부 계산 정밀도가 높을 수 있습니다.

`studio/timeline.py`가 영상·오디오·자막에 사용하는 공통 EDL을 계산합니다. 편집할 때마다 이전 출력 시각을 다시 고치는 방식으로 누적 보정하지 않습니다. 현재 편집 데이터에서 항상 처음부터 매핑합니다.

## EDL 계산

클립을 `[start, end)`로 정의합니다. 삭제 범위를 클립 경계에 맞춰 자르고 시작 시각으로 정렬한 뒤, 겹치거나 맞닿은 삭제 범위를 합칩니다. 남긴 구간은 원본 순서를 유지하며 떨어진 발화를 임의로 재배열하지 않습니다.

남긴 구간이 `S_i = [a_i, b_i)`이고 배속이 `v`이면 다음과 같습니다.

```text
출력 길이 = Σ(b_i - a_i) / v
구간 i의 출력 시작 = Σ(j < i)(b_j - a_j) / v
구간 i 안의 원본 시각 t의 출력 시각
  = 구간 i의 출력 시작 + (t - a_i) / v
```

예를 들어 원본 `[0,10)`초에서 `[4,6)`초를 삭제하고 1.25배를 적용하면 남긴 구간은 `[0,4)`, `[6,10)`이고 출력 길이는 `(10-2)/1.25 = 6.4`초입니다. 원본 8초는 출력 4.8초에 대응합니다. 삭제한 원본 5초는 출력에 대응하는 표시 구간이 없습니다.

`source_time()`은 출력 시각으로부터 원본 시각을 찾고 `mapped_cues()`는 자막을 남긴 각 구간과 교차시킨 뒤 같은 식으로 매핑합니다. 삭제 경계를 걸치는 자막은 여러 표시 구간으로 분리되고 원본 자막 ID를 보존합니다. 같은 자막의 남은 텍스트를 자동으로 다시 쓰지는 않습니다. 문맥·단어 단위 수정은 편집자가 확인해야 합니다.

빈 클립, 역전 시간, 음수 시작, 유한하지 않은 숫자, 지원 범위 밖 배속, 모두 삭제한 클립은 출력 전에 거부합니다. 앱 저장 API는 0.5~2배를 허용하고 UI는 0.75~2배 선택지를 제공합니다. 내부 EDL 함수의 0.25~4배 허용 범위는 앱 전체의 지원 범위를 뜻하지 않습니다. 저장 API는 클립 범위 밖 삭제를 거부합니다. 내부 계산에서는 범위 밖 삭제를 잘라 계산하며, 겹친 삭제가 두 번 적용되지 않습니다.

## 실제 인코딩과 프레임 반올림

FFmpeg는 원본 클립 범위를 읽고 남긴 구간을 같은 시간 범위로 `trim/atrim`합니다. 각 구간의 시작 PTS를 정리하고 이어 붙인 뒤 영상 `setpts=PTS/v`, 음성 `atempo`를 **전체에 한 번** 적용합니다. 큰 배속은 FFmpeg가 지원하는 `atempo` 범위로 나누어 연결합니다. 음성은 높이 보존을 목표로 하고 48kHz AAC로 인코딩합니다.

출력 영상은 30fps로 샘플링하므로 연속 시간의 이벤트가 프레임 경계에 놓입니다. 자막 표시 시작·끝은 `ceil(t × 30 - 1e-7)` 프레임으로 계산합니다. 이는 자막이 해당 이벤트 이전 프레임에 나타나는 것을 방지하며 최대 약 33.34ms의 한 프레임 양자화 오차를 만듭니다. 표시 구간은 시작 프레임을 포함하고 끝 프레임은 제외합니다. UI 확정 프레임은 요청 시각을 30fps의 프레임 시작으로 내립니다.

SRT의 시간은 같은 매핑 결과를 밀리초로 반올림해 저장합니다. 인코더의 AAC 지연과 영상의 프레임 경계 때문에 메타데이터의 길이와 연속 계산 길이가 완전히 같지 않을 수 있습니다. 렌더러는 출력 코덱·해상도·음성 유무·길이를 검사하며 길이 오차 허용치는 최대 0.15초입니다. 인수 검수에서 실제 측정한 길이·동기화 오차는 별도 검증 기록에 남깁니다. 이 허용치는 한국어 ASR 단어 시간의 정확도를 보증하지 않습니다.

## 미리보기와 최종 합성

제목·텍스트 로고·일반/강조 자막을 Pillow로 1080×1920 RGBA 이미지에 그립니다. 글꼴 선택, 실제 글자 너비, 명시적 줄바꿈, 자동 줄바꿈, 외곽선과 배경을 같은 함수에서 처리합니다. 한 행의 모든 글자는 최대 ascender 기준의 공통 기준선을 사용하므로 소수점·쉼표와 서로 다른 크기의 강조 글자도 같은 행에 놓입니다. 최종 MP4에는 이 PNG 레이어를 FFmpeg로 합성합니다. 확정 미리보기 PNG도 같은 레이어와 EDL을 사용하므로 CSS 글자 렌더링과 별도로 자막을 다시 계산하지 않습니다.

사용자 이미지 로고·배경도 같은 정규화된 PNG 자산으로 합성합니다. 프로젝트 JSON에는 자산 ID만 저장하고, 백엔드가 데이터 폴더의 실제 파일로 해석합니다. 사용자 입력에 포함된 직접 파일 경로는 스타일에서 제거하므로 임의 경로를 렌더러에 전달하지 않습니다.

자막 PNG의 표시 이벤트도 같은 30fps 경계로 구분합니다. 강의 영상은 기본 `contain`으로 비율을 유지해 상자 안에 넣고 남는 부분을 배경색으로 채웁니다. 사용자가 확대/크롭을 선택하거나 상자를 캔버스 밖으로 이동하면 자료가 잘릴 수 있어 경고합니다. 기본값에서 가장자리 자료가 보존되는지는 모서리 표식 영상으로 검수합니다.

브라우저의 드래그·상자 표시는 편집 조작입니다. 저장 후 서버가 만든 확정 프레임 또는 렌더된 미리보기 영상이 검수 기준입니다. 글꼴 파일은 시스템에서 읽으므로 Windows와 Linux 사이에 글꼴 선택 차이가 있을 수 있습니다. 동일 컴퓨터의 미리보기와 출력 일치, 다른 컴퓨터에서의 동일 자산 재현은 서로 다른 조건입니다.

## 원본·리비전·되돌리기

원본은 업로드 바이트의 SHA-256 이름으로 `sources/`에 저장하며 편집하지 않습니다. 텍스트 수정은 프로젝트의 현재 `cues`를, 실제 구간 삭제는 클립의 `cuts`를 변경합니다. 불러온 전사의 원문은 `original_cues`로 따로 남깁니다.

프로젝트 저장은 임시 JSON 작성·파일 동기화·원자적 교체를 사용하고 리비전을 증가시킵니다. 이전 저장본은 `history/<프로젝트ID>/`에 따로 보관합니다. 프런트엔드의 실행 취소/다시 실행은 현재 세션의 편집 상태를 되돌리며 이 영속 파일 기록과 구분합니다. 이전 파일은 프로젝트 가져오기로 사본을 복원할 수 있습니다. 여러 탭의 오래된 리비전 저장은 409 충돌로 거부합니다.

렌더 작업은 시작 시점 프로젝트의 사본을 사용합니다. 출력 중 프로젝트를 수정해도 이미 실행 중인 출력의 내용이 조용히 바뀌지 않습니다. 새 출력은 임시 파일로 만들고 실제 미디어 검사를 통과한 뒤 완료본으로 이동합니다. 취소·실패가 원본이나 직전 성공본을 지우지 않습니다.
