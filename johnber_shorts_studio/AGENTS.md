# 작업 규칙 (존버나드 쇼츠 스튜디오)

이 폴더에서 작업하는 사람·에이전트를 위한 규칙입니다. 상위 폴더의 ETF Analyzer 파일은 이 프로젝트 작업 중 수정하지 않습니다.

1. 시작 전 `PROGRESS.md`, `IMPLEMENTATION_PLAN.md`, `docs/TEST_RESULTS.md`를 읽는다. 작업 후 `PROGRESS.md`를 갱신한다.
2. 화면만 있는 기능을 만들지 않는다. 동작하지 않는 기능은 숨기거나 ‘준비 중’ 배지로 표시한다.
3. 미리보기와 출력은 반드시 `app/layout.py`(텍스트·장면)와 `app/edl.py`(시간)를 함께 쓴다. 브라우저 쪽에서 글자를 따로 그리지 않는다.
4. 사용자 원본 파일을 수정·삭제하지 않는다. 출력은 임시 파일 → ffprobe 검사 → 완료 폴더 순서로만 만든다.
5. FFmpeg 등 외부 프로그램은 인자 배열로 실행한다(셸 문자열 연결 금지).
6. API 키를 코드·로그·커밋에 넣지 않는다. 오류 메시지는 `config.redact()`를 거친다.
7. 외부 API는 사용자 확인(전송 데이터·예상 비용) 뒤에만 호출한다. 키가 없을 때 가짜 결과를 만들지 않는다. 존재하지 않는 모델명·요금을 하드코딩하지 않는다.
8. 결제·실제 계정 게시·외부 공개 배포·관리자 권한 변경은 사용자 승인 없이 하지 않는다.
9. 검수 결과는 PASS / FAIL / BLOCKED / NOT RUN으로 기록하고, 실행하지 않은 것을 통과로 쓰지 않는다. Linux 결과를 Windows 결과로 쓰지 않는다.
10. 테스트: `python -m pytest tests -q`(필수), 화면 변경 시 `tests/ui_e2e.py`·`tests/ui_preview_match.py`도 실행.
11. 참고 서비스(ENLIT)의 로고·템플릿 이미지·글꼴·브랜드를 복제하지 않는다. 새 글꼴은 라이선스를 `fonts/`에 함께 둔다.
12. DB 구조를 바꾸면 `app/db.py`의 `MIGRATIONS`에 새 항목을 추가한다(기존 항목 수정 금지).
